# Phase 6 统一切换控制契约

- 文档编号：phase-6/00
- 状态：仓库控制契约已定义；生产执行证据待现场生成

## 不可变边界

统一切换是一次性人工变更，不由 CI、ERP API、MCP 或 AI 自动触发。受保护工作流只读取 WORM 导出的脱敏证据并给出机器可验证结论，不持有生产凭据、不调用部署接口、不修改 DNS/网关、不冻结旧系统，也不执行回滚。

生产职责必须一次性切换，禁止按业务域形成长期双写。切换窗口采用 `Asia/Shanghai` 连续窗口，实际冻结至开放耗时不得超过 8 小时。任一停止条件触发后，由事故指挥官按已批准 Runbook 决定回滚；回滚目标为 4 小时内恢复旧系统安全写入能力。

## 前置门禁

- Phase 5 Go/No-Go 结论必须为 `GO`，且决定、所有下游证据和计划窗口都未过期。
- 三次全量演练必须绑定同一发布候选 commit、三份镜像摘要和部署清单；三次证据 ID 与摘要均独立。
- 生产级回滚演练必须覆盖 MongoDB/对象、身份、DNS/网关、钉钉、飞书、OP、e签宝、队列和 MCP，并证明业务效果无丢失、无重复、无越权。
- 未关闭 Sev1/Sev2、Critical/High 漏洞、权限差异、记录差异、未解释金额差异、缺失附件和校验和差异均为零。

## 固定步骤与双人复核

证据必须按以下顺序记录，步骤不得缺失、重复或并行越序：

1. 建立事故指挥与通信桥；
2. 冻结旧系统写入；
3. 迁移最终增量；
4. 完成数据与权限全量对账；
5. 切换统一身份入口；
6. 切换 DNS/网关；
7. 切换钉钉、飞书、OP、e签宝、银行、税务、附件、WORM 和消息连接；
8. 完成业务抽样；
9. 完成 MCP OAuth、协议、资源、提示、Tool 与跨租户拒绝冒烟；
10. 开放 ERP 写入；
11. 将旧系统锁定为只读；
12. 移交生产监控与 Hypercare 值班。

每一步必须记录开始/结束时间、独立操作证据、独立复核证据和内容 SHA-256；操作人与复核人不得共用证据 ID。证据正文、姓名和生产配置只进入企业 WORM，GitHub 仅保存脱敏 verdict。

## 连接验收

钉钉、飞书、OP、e签宝、银行、税务、附件、WORM、消息和 MCP 十类连接必须全部通过冒烟和对账。凭据不得写入证据，旧 Token 不得透传到 MCP。ERP 仍是组织与员工唯一主数据源，外部平台只能接收版本化下发和回执。

## 停止与回滚条件

以下任一条件立即停止开放：Sev1/Sev2、跨租户访问、金额或权限未解释差异、不可恢复数据丢失、身份入口失败、关键连接不可用、MCP OAuth/跨租户拒绝失败、预计窗口超时。AI 只能解释状态，不得决定忽略条件、批准例外、启动切换或执行回滚。
