# GaoQ-OS 项目章程与阶段门禁

## 1. 产品定位与边界

GaoQ-OS 是以组织人事、审批、招聘、入职、培训、薪酬和员工关怀为核心，以 MCP 为标准 AI 入口的企业运营底座。MCN、广告、招商团长、返利、PE/CVC 等经营业务继续由 OP 承载，并通过标准集成层与 ERP 交换身份、组织、审批和经营摘要。

当前范围不包含财务总账、应收应付、库存、采购和供应链。新增这些领域必须单独立项，不得在现有 Issue 中隐式扩张。

## 2. 已冻结决策

| 决策 | 结论 |
| --- | --- |
| 交付周期 | 12–15 个月 |
| 团队容量 | 8–12 人，覆盖产品、架构、前后端、测试、DevOps 与安全 |
| 部署基线 | 中国境内云私有 VPC，开发、测试、预发、生产、灾备隔离 |
| 架构形态 | NestJS 模块化单体，达到独立扩缩或治理需要后再拆服务 |
| 主数据 | ERP 是员工、部门、岗位、职级的唯一权威源 |
| 多租户 | Phase 0 起强制，所有数据和运行上下文必须具备租户边界 |
| 办公平台 | 钉钉、飞书首期同时正式接入 |
| MCP | 当前稳定规范；远程 Streamable HTTP，本地 stdio；不兼容旧 HTTP+SSE |
| AI 写操作 | 风险分级，普通写需确认，高风险需二次认证和审批 |
| 电子签 | 统一适配层，首发 e签宝 |
| 薪税发放 | 银行代发文件、回盘、税务申报文件和自动对账；预留直连 |
| 上线方式 | 统一大切换，强制影子运行、三次演练和可验证回滚 |

## 3. 治理角色

| 角色 | 核心责任 | 不可委托的批准事项 |
| --- | --- | --- |
| 项目发起人 | 预算、范围、业务优先级 | 统一上线 Go/No-Go |
| 产品负责人 | 需求、流程、验收口径 | 产品范围和业务验收 |
| 首席架构师 | 领域边界、契约、ADR、跨模块一致性 | 架构基线与例外 |
| 安全负责人 | 威胁模型、隐私、权限、审计、供应链安全 | 安全门禁和高风险例外 |
| 数据负责人 | 主数据、质量、迁移、保留与删除 | 数据口径和迁移验收 |
| HR/财务/法务负责人 | 专业规则和合规审核 | 薪酬、合同、隐私业务验收 |
| QA负责人 | 测试策略、质量报告、缺陷分级 | 发布质量结论 |
| SRE/DevOps负责人 | 环境、发布、监控、灾备、回滚 | 生产变更和恢复结论 |

## 4. 阶段计划

| 阶段 | 工期 | 核心交付 | 强制退出条件 |
| --- | --- | --- | --- |
| Phase 0 | 4–6周 | 规范包、ADR、契约、威胁模型、Backlog | 架构/安全/业务共同签署；所有 P0 项达到 DoR |
| Phase 1 | 8–10周 | 工程底座、多租户、身份、组织主数据、集成底座、MCP Core | 租户逃逸测试为零；双平台身份与组织对账100%；MCP授权可用 |
| Phase 2 | 8–10周 | 审批、表单、流程、PC/H5、审批 MCP | 状态机、并发、权限、通知、确认链路全部验收 |
| Phase 3 | 10–12周 | 招聘、e签宝、入职、知识培训、关怀及 MCP | 候选人到员工全链闭环；签署证据和隐私授权可审计 |
| Phase 4 | 10–12周 | 考勤、薪酬、薪税文件、发放回盘、对账及 MCP | 两个完整薪资周期影子计算；未解释差异为零 |
| Phase 5 | 8–10周 | OP 完整桥接、移动端、分析、生产加固、迁移工具 | 性能、安全、容灾、集成和全量迁移预验收通过 |
| Phase 6 | 6–8周 | 三次演练、统一切换、回滚、四周 Hypercare | Go/No-Go 条件全部满足，遗留系统进入只读归档 |

## 5. 项目级质量目标

- 核心服务月度可用性不低于 99.9%。
- API P95 响应时间小于 500ms；支持 1000 并发用户。
- 1000 人月度薪酬计算在 5 分钟内完成。
- 生产 RPO 不高于 15 分钟，RTO 不高于 4 小时。
- 全系统单元测试覆盖率不低于 80%；租户、权限、审批、薪酬、加密和 MCP 确认服务不低于 90%。
- Sev1/Sev2 缺陷、跨租户访问、未解释薪酬差异和未审计高风险操作均为零才可上线。

## 6. 阶段变更控制

范围、权威数据源、公开接口、安全门禁、MCP风险级别或上线方式发生变化时，必须新建 ADR 和变更 Issue。未经批准不得通过修改实现来事实改变架构决策。
