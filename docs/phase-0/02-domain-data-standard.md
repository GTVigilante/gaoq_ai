# GaoQ-OS 领域与数据规范

## 1. 主数据权威

| 数据 | 权威领域 | 下游 |
| --- | --- | --- |
| 租户与功能开关 | Tenant | 全模块、集成网关、MCP |
| 员工、部门、岗位、职级 | Org | 钉钉、飞书、OP、审批、薪酬、培训 |
| 外部身份映射 | Identity | SSO、钉钉、飞书、MCP |
| 角色、权限、数据范围 | Security | Web、MCP、API、导出、队列 |
| 候选人和Offer | Recruitment | Onboarding、e签宝、Org |
| 考勤月结快照和薪资结果 | Payroll | 审批、银行文件、员工薪资单 |

系统首次启用允许从钉钉、飞书和旧系统导入并人工仲裁；基线确认后，外部平台不得反向覆盖 ERP 主档。考勤、日历回执等外部事实按专门契约入站，不改变组织主数据权威。

## 2. 身份、状态与角色分离

- `Person` 表示自然人，负责去重和法定身份引用。
- `UserAccount` 表示可登录账号，可关联员工、候选人、外部合作方或校友主体。
- `Employment` 表示劳动关系，状态为 `candidate/preboarding/probation/active/suspended/resigned`。
- `RoleAssignment` 表示在指定租户、组织范围和有效期内授予的权限角色。
- `Candidate`、`Employee`、`Alumni` 不作为可继承角色；角色不隐式表达雇佣状态。

## 3. 多租户强制规则

1. 所有业务集合必须包含 `tenantId`，并建立以 `tenantId` 开头的联合索引。
2. Repository 构造时必须绑定 `TenantContext`；禁止提供无租户过滤的通用查询入口。
3. 唯一约束默认是租户内唯一；跨租户共享数据必须进入专门的 Platform 领域。
4. 缓存键、对象路径、队列名称/载荷、搜索索引、导出文件和审计事件必须包含租户边界。
5. 后台任务必须携带签名后的主体与租户上下文；缺失上下文时拒绝执行。
6. 跨租户运维采用受审计的 break-glass 流程，默认禁用并限时授权。

## 4. 通用字段与删除策略

```typescript
interface EntityMetadata {
  tenantId: string;
  version: number;
  createdAt: Date;
  createdBy: string;
  updatedAt: Date;
  updatedBy: string;
  isDeleted: boolean;
  deletedAt?: Date;
  deletedBy?: string;
}
```

- 法定凭证、薪酬、签署证据和审计记录不使用普通软删除；按保留策略归档并限制访问。
- 普通业务数据软删除后必须从默认查询、搜索和缓存中排除。
- 更新使用 `version` 乐观锁；并发冲突返回 HTTP 409 和可恢复业务错误。

## 5. 金额、规则与历史

- 金额使用整数分 `amountMinor` 或 Decimal128，禁止 JavaScript `number` 参与最终财务计算。
- 薪酬、税率、社保、公积金、合同、审批模板和组织任命均保存版本、生效区间和批准记录。
- 薪资计算必须保存员工/考勤/规则输入快照、计算步骤、舍入策略、输出和结果哈希。
- 已发布审批实例保存表单、流程、审批人解析结果和模板版本的完整快照。
- 所有状态迁移通过显式命令完成，校验来源状态、操作者权限、业务条件和幂等键。

## 6. 敏感数据与检索

| 等级 | 示例 | 存储与使用要求 |
| --- | --- | --- |
| L1 公开 | 已发布公告、公开职位 | 完整性保护和内容审核 |
| L2 内部 | 组织通讯录、培训资料 | 登录、租户与部门权限 |
| L3 敏感 | 手机、邮箱、简历、面试反馈 | 字段加密、脱敏、目的限制、访问审计 |
| L4 高敏 | 身份证、银行卡、薪酬、合同、密钥 | KMS信封加密、二次认证、最小权限、完整审计 |

- L3/L4 使用 AES-256-GCM 数据密钥，主密钥由云 KMS 管理并按策略轮换。
- 需要唯一或精确查询的字段保存密文和标准化 HMAC 盲索引；禁止对明文或随机密文建立文本索引。
- 列表、日志、MCP、导出和通知默认返回脱敏值；解密必须经过字段权限和目的校验。

## 7. 数据生命周期

每类数据必须登记收集目的、法定依据、来源、共享对象、存储位置、保留期、删除/匿名化方式和负责人。候选人、校友关系、简历、身份证、银行卡等数据需提供授权撤回和到期清理流程；备份中的删除通过密钥销毁和备份到期实现。

## 8. 数据质量门禁

- 主数据完整性、唯一性、引用一致性、有效期和状态迁移均有自动规则。
- Repository 读取必须使用可信租户和白名单查询参数，只选择业务所需最小投影；
  Mongo 返回对象须反向绑定查询租户、对象/关联标识、状态、版本和时间/证据组合，
  不能因查询过滤器理论上已限定就信任受损持久化结果。
- 顺序号分配、插入、CAS 状态更新和 Outbox 等事务写入必须运行时确认活动事务；
  创建/更新结果须反向绑定预期对象、版本和终态，空结果、多结果、错对象或错终态
  必须使事务失败。数据库原始异常保留给应用层分类，禁止伪造成功。
- 外部同步每日生成数量、字段、版本和失败对账报告。
- 迁移采用可重复脚本，输出来源数、目标数、拒绝数、重复数、校验和及差异清单。
- 未经数据负责人签署的差异不得在统一大切换中豁免。
