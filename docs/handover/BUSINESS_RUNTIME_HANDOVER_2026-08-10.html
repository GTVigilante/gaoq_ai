一、结论

架构师提出需要 Interpreter 的判断正确。生产解释层必须共同约束 Schema 版本、来源、权限、类型、查询、记录版本、证据和命令边界。本切片已将它实现为版本化 Dataset Runtime。拖拽表单、多维 Base、审批、自动化、REST、MCP 和 CLI 使用同一语义；OP 继续是唯一事实源，数据不会复制为表单或 Base 的私有记录，运行时也不直连 OP 数据库。

二、已实现能力

Dataset Runtime 与 OP 引用

  • 原生引用绑定 datasetId + schemaRevision；外部引用绑定 system + objectType + schemaVersion。
  • 记录引用绑定 recordId + version；Schema、来源或版本漂移时失败关闭。
  • 首个外部数据集为 op / operating_summary / 1.0，只经 OP 应用服务读取。
  • L3/L4 字段不进入通用投影；查询仅允许有界等值精确查询。

表单、审批与多维 Base

  • 拖拽字段新增 dataset_reference，可选择显示字段和审批快照字段。
  • 提交审批时固定来源 Schema、记录版本、观察时间、最小字段和内容摘要。
  • Base 可挂原生 Table 和只读 External Table，Grid 通过同一 Runtime 读取。
  • 动态表单到审批模板由服务端编译；发布修订不可被覆盖。

自动化

  • base_automation_runs 保存不可变计划、来源版本、进度、最小结果和稳定失败码。
  • Worker 可幂等发起审批、创建原生记录、更新来源记录；自动化写入 v1 不级联。
  • 通知和 Connector/OP Command 尚无正式 Adapter，任何副作用前转 manual_review。

外部接口

  • MCP 新增 dataset_catalog、dataset_record_resolve，均为只读 R0。
  • CLI 新增 bases list、datasets list、datasets resolve --file。
  • OpenAPI：53 Controller、272 路由声明、278 操作、123 DTO Schema；AsyncAPI：189 事件。
