# ERP Web 基础无障碍与响应式门禁

## 1. 适用范围

本门禁覆盖 Phase 1 的应用骨架、SSO 登录、PC 工作台导航、组织管理与 H5
工作台。它把以下基础要求固定为仓库契约：

- 根文档使用 `zh-CN` 和设备宽度视口；
- 键盘用户可以跳过重复导航并直接聚焦主内容；
- 登录、组织和移动入口具备主地标、一级标题、加载与错误语义；
- PC 与 H5 导航具备可访问名称，移动当前位置使用 `aria-current`；
- 所有原生交互元素使用全局高可见焦点，移动高频操作热区不小于 48px；
- 系统请求减少动画时，全局动画与过渡收敛到单次最短时长；
- 820px PC 收窄、768px H5 扩展、560px 与 520px 小屏断点不可静默删除；
- 浏览器不得通过 Local Storage、Session Storage 或 IndexedDB 持久化身份与
  业务数据，租户、角色和数据范围只消费服务端可信结果。

## 2. 执行

```bash
pnpm quality:erp-web-accessibility
```

该命令运行基础入口与移动样式的独立 Vitest 契约，并纳入 `pnpm precheck`。
普通 `pnpm test` 仍会重复执行这些测试，防止专项目标与工作区测试产生分叉。

## 3. 失败处理

缺少地标、标题、可访问名称、可见焦点、减少动画策略、断点或可信权限文案时，
门禁直接失败。不得通过放宽断言、隐藏交互元素或在客户端复制授权规则规避失败。
服务端授权仍是最终强制点；前端隐藏按钮不能替代 API 权限校验。

## 4. 外部验收边界

静态源代码和组件契约不能证明浏览器真实排版、读屏顺序、焦点陷阱、缩放、
高对比模式或中文语音质量。Issue #11 的最终验收仍须在代表性 Chrome、Safari
与移动浏览器上，以 375px、768px 和桌面宽度执行键盘、200% 缩放、主流读屏器
与 WCAG 2.2 AA 自动扫描；发现阻断项后必须回到代码和门禁修复，禁止用人工声明
替代实体证据。
