# ADR-0002：ERP 主数据权威与双办公平台适配

- 状态：accepted
- 日期：2026-07-20
- 关联 Issue：#2、#7、#8、#12、#32
- 替代关系：无

## 背景

员工和组织同时存在于 ERP、钉钉、飞书和 OP。允许多个系统互相覆盖会导致身份
合并、审批路由、薪酬输入和离职权限失效不可审计。

## 决策

ERP 是员工、Person、Employment、部门、岗位和职级的唯一权威源。受控首次导入
完成后只允许 ERP 向钉钉、飞书、OP 和专业算薪发布版本化最小投影；外部组织字段
不得回写主档。钉钉和飞书首期同时作为一级适配器交付，OP 使用独立服务身份。

外部 IdP 只证明认证结果，ERP 仍按已绑定 `externalTenantId + unionId + userId`
裁决主体和授权；手机号/邮箱冲突必须人工仲裁。组织下发采用事务 Outbox、单调
版本、确定性幂等、每日全量差异和失败恢复。

## 后果

- 审批、招聘、薪酬、MCP 和下游同步使用同一组织事实。
- 外部平台本地修改不会自动成为 ERP 真相，运维必须处理差异和冲突队列。
- 双平台适配器需要同步维护字段映射、权限、限流和对账证据。

## 被否决方案

- 钉钉或飞书作为组织主档：造成双平台不对称并锁定供应商。
- 按“最后写入者胜出”双向同步：无法证明权威和版本，可能形成权限绕过。
- 用手机号/邮箱自动合并身份：存在接管和跨人员错误绑定风险。

## 安全与数据影响

联系方式只经短时私密开户通道处理，不进入普通 Outbox、日志、MCP 或通用幂等
响应。适配器 Token 不持久化、不透传业务模块。
