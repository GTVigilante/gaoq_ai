# ADR-0004：独立专业算薪生产事实源

- 状态：accepted
- 日期：2026-07-29
- 关联 Issue：#5、#27、#28、#29、#30、#31、#108
- 替代关系：收敛并冻结 Phase 4 早期“ERP 内部算薪可用于生产”的隐含假设

## 背景

ERP 仓库包含版本化薪酬、影子计算、银行/税务和迁移兼容控制面，但生产工资需要
专业规则治理、独立职责域和明确的唯一事实源。并行生产事实会导致金额、审批、
薪资单、银行和税务对账无法确定权威。

## 决策

独立专业算薪系统是工资唯一生产事实源；ERP 是人员/组织和授权主数据源。
`@gaoq/platform-contracts@1.0.0` 是双方身份、主数据、整数分金额、七类
CloudEvents 和运行时 JSON Schema 的共享契约。专业算薪提供独立 OAuth Resource
Server/MCP，本人查询由用户主体解析 employee，不接受 ERP 服务 Token 加客户端
employeeId 代查。

ERP 默认 `PAYROLL_SYSTEM_MODE=external`，在应用服务层对旧 Payroll/Treasury
在线、MCP、Worker、迁移和内部调用旁路失败关闭。仓库内计算/发放代码只用于迁移、
影子验证、兼容和回滚证据，不得恢复为生产事实源。

## 后果

- 上线前必须完成共享事件、快照、两个影子周期、断连恢复、银行/税务和双方 MCP
  的真实联调。
- ERP 可展示经授权的专业算薪最小投影，但不能伪造生产工资终态。
- 更换事实源或恢复 ERP 算薪必须新 ADR，并重新执行 Phase 4–6 全部门禁。

## 被否决方案

- ERP 与专业算薪双主运行：无法保证金额和终态唯一。
- ERP 以服务身份代查任意员工薪资：形成越权代理。
- 仅靠文件人工同步：缺少实时状态、事件回放和可验证恢复。

## 安全与数据影响

工资与账户为 L4。跨系统只共享最小主数据、状态、摘要和本人授权投影；禁止共享
工资正文、银行账户、Token 或上游错误正文。
