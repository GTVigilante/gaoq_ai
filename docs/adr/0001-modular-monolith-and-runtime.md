# ADR-0001：模块化单体与运行时基线

- 状态：accepted
- 日期：2026-07-20
- 关联 Issue：#1、#2、#6、#12
- 替代关系：无

## 背景

项目覆盖身份、组织、审批、招聘、入职、知识、关怀、考勤、薪酬桥接、分析与
MCP。当前团队规模不足以承担大量分布式服务带来的事务、契约、部署和观测成本，
但敏感领域仍需要清晰边界和独立 Worker。

## 决策

采用 NestJS ESM 模块化单体作为业务 API，Next.js App Router 承载 ERP Web 和
官网；MongoDB Replica Set 提供事务，Redis/BullMQ 承载短时状态与后台任务，
Helm/Kubernetes 作为生产编排基线。领域模块只能通过应用服务/端口协作，Worker
只装配后台任务所需最小依赖图。达到独立扩缩、合规隔离或团队自治的可量化条件后，
通过新 ADR 拆分服务。

多租户从入口到 Repository、缓存、队列、对象、事件和审计强制执行；可信
`tenantId` 只来自已验证身份/服务上下文。

## 后果

- 单仓事务和一致性更简单，早期交付和回滚成本较低。
- 模块边界、运行时 schema、Outbox/Inbox 和依赖方向必须持续由测试约束，否则
  单体会退化为共享数据库耦合。
- API 与 Worker 可独立部署和扩缩，但共享版本化契约与镜像发布候选。

## 被否决方案

- 首期全面微服务：团队和运行复杂度过高，分布式事务风险大。
- 单进程 API + Worker 混合运行：放大攻击面和故障域。
- 无 Replica Set 的单节点 MongoDB：不能满足事务与生产恢复基线。

## 安全与数据影响

Secret 只由 Secret Manager/Kubernetes Secret 注入；L3/L4 使用独立密钥域和
AES-256-GCM/盲索引。模块化单体不授权跨模块直查敏感集合。
