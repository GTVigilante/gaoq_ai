# ADR-0006：统一切换与证据门禁

- 状态：accepted
- 日期：2026-07-20
- 关联 Issue：#13、#14、#35、#37、#38、#39、#40
- 替代关系：无

## 背景

身份、组织、审批、招聘、薪酬桥接和外部连接存在强依赖。按领域长期双写或分批
生产切换会形成多个事实源，增加权限、金额、事件和回滚不一致。

## 决策

采用统一大切换。切换前完成三次全量迁移演练、生产等价性能/安全/容灾/集成
预验收、两个薪资影子周期和可验证回滚；切换窗口执行冻结、增量迁移、连接切换、
双人复核和旧系统只读。上线后连续 28 天 Hypercare，每日对账，最终由法务、
财务和数据负责人批准只读归档，归档批准不授权删除。

Phase 5/6 证据使用版本化严格 schema、当前 commit/镜像/部署清单/环境绑定、
职责分离的独立 Ed25519 签名、公钥 keyset 摘要和 WORM 原始材料。仓库自测只能
验证校验器失败关闭，不能生成生产通过结论。

## 后果

- 任一 Sev1/Sev2、跨租户访问、高危漏洞、未解释工资差异、迁移拒绝、恢复目标
  或职责签名不满足，均保持 No-Go。
- 统一切换协调成本较高，但生产事实源和回滚点明确。
- Hypercare 满 28 日、每日证据和归档签署前，旧系统不能进入最终归档状态。

## 被否决方案

- 按模块渐进生产切换：长期双写和事实源漂移风险过高。
- 无影子周期直接切换工资：无法证明金额差异为零。
- 仅凭会议纪要或单一签名批准上线：不能验证职责分离和证据完整性。

## 安全与数据影响

迁移、发布和切换证据只含摘要、计数、环境和引用，不含个人/工资/合同正文。
WORM 与角色私钥位于独立权限域，应用仓库不保存任何生产私钥。
