# Phase 2 UAT 与安全验收

## 验收规则

每项必须记录环境、构建 SHA、租户、执行人、时间、输入摘要、预期、实际结果和证据链接。L3/L4 数据、Token、Cookie、密钥和确认凭据不得进入截图或工单正文。

## 功能与一致性

- [ ] 模板草稿、双人复核发布、修订和退役符合状态机；实例永久使用提交时快照。
- [ ] 条件 DSL 只允许白名单字段/操作符；未知字段、超深、超节点和类型不匹配失败关闭。
- [ ] 草稿提交后按 ERP 有效员工、角色、部门经理解析审批人；停用员工不能进入新待办。
- [ ] 或签、会签、拒绝、委托、转交、加签、撤回、归档均覆盖成功、越权、重复和并发版本冲突。
- [ ] R1 PC 转交固定来源为当前可信主体，目标必须是同租户有效 ERP 主体；成功后原待办取消、新待办与时间线一致。
- [ ] R1 PC 加签只允许当前会签节点；或签、重复主体、停用主体、无 Scope、旧版本和重复副作用全部失败关闭。
- [ ] PC 委托只允许本人创建、最长 30 天、时间不重叠；自委托、代他人委托、停用/跨租户代理人、旧版本撤销和重复请求全部失败关闭。
- [ ] 委托创建/撤销与最小披露 Outbox 事件同事务；内部事件和审计只包含可信租户路由与最小授权摘要，不含权限快照；浏览器响应、幂等响应和 MCP Resource 不含租户字段。
- [ ] PC/H5 从待办进入详情与 R1 决策不超过三步；动作时间线按聚合版本递增且与最终状态一致。
- [ ] PC 只列出当前可信租户的已发布模板；模板目录及浏览器状态不出现租户、流程节点、解析器或发布审批人字段。
- [ ] PC 按字段类型创建草稿并以强版本提交；模拟“创建成功、提交失败”后只重试原草稿和原提交幂等键，不产生第二个草稿。
- [ ] H5 从已发布模板发起 R1/R2 审批；非法日期、金额非整数分、未知选项、重复文件引用和伪造 tenantId 均失败关闭或被白名单丢弃。
- [ ] H5 在创建响应丢失时复用原请求正文和创建幂等键；在提交响应丢失时复用原草稿版本和提交幂等键，刷新页面前不产生重复实例或动作。
- [ ] H5 R1 转交/加签只在对应 Scope 存在时呈现；响应丢失后复用原目标、版本和幂等键，R2 不出现普通写入口。
- [ ] H5 委托创建/撤销遵守本人、最长 30 天、不重叠和强版本边界；AI 工具目录无委托写 Tool。
- [ ] H5 在写入待重试期间切换可信登录主体时，旧主体的表单正文、目标、版本和幂等键全部从内存清除。
- [ ] R2 模板禁止发起人自批；MCP 决策对所有模板额外执行独立审批约束。
- [ ] 直接调用普通 REST 的 R2 决策、转交和加签均返回 `APPROVAL_R2_STRONG_AUTH_REQUIRED`，且动作、Outbox、通知和聚合版本完全不变；已确认 MCP R2 决策仍可执行。
- [ ] 相同 `Idempotency-Key` 同请求重放相同结果，不同请求返回冲突，不重复产生动作、事件或通知。
- [ ] 审批聚合、动作、Outbox、双通道通知意图任一写入失败时事务整体回滚。
- [ ] 十五类审批 Outbox 事件逐项核对 CloudEvent type/subject/data 与事务记录；
  非规范时间、未知字段、伪造租户/聚合/版本、结果与终态冲突、代理标记错位、
  重复撤回收件人和超期委托均在写入前失败关闭，OP 结果桥不得消费受损事件。

## 多租户与数据保护

- [ ] REST/MCP/运维接口传入伪造租户字段、Header 或查询对象均不能改变可信租户。
- [ ] 跨租户实例 ID、通知 ID、操作 ID 均返回不存在或拒绝，不泄漏资源状态。
- [ ] MongoDB 中审批表单为 AES-256-GCM 密文；AAD 错误、密文篡改和未知 key id 均失败关闭。
- [ ] Outbox、通知、MCP 确认、审计和幂等响应不含表单正文、平台 Token、Cookie、Secret 或银行/身份敏感值。
- [ ] L3/L4 字段对普通审批人和 MCP 默认脱敏；仅服务端授权主体可读取。

## 通知与外部平台

- [ ] 提交、流转、转交、加签、终态和撤回取消待办生成正确收件人；已完成会签人不重复接收待办。
- [ ] 钉钉和飞书分别成功发送并记录平台回执；平台 Token 仅存在于 Worker 内存。
- [ ] 401 使当前缓存令牌失效；飞书 408/429/5xx 使用同一 `uuid` 退避；业务错误和最大次数进入死信。
- [ ] Worker 在发送前、发送后落库前、持有租约超时三个故障点重启，审批状态均不变化；平台发送成功后的终态写入故障不得反向登记发送失败。
- [ ] 飞书 `uuid` 去重有效；钉钉过期执行租约、网络/读取错误、5xx 或成功响应缺少回执时进入 `APPROVAL_NOTIFICATION_DELIVERY_INDETERMINATE`，不自动重发。
- [ ] 结果不确定的钉钉死信只有在平台对账后才能使用 `approved_exception` 人工恢复；其他修复原因必须失败关闭。
- [ ] 通知运维 REST 的四类恢复原因分别只命中凭据、身份、Provider 和已批准
  结果不确定错误；跨类原因、未知正文、非规范分页、超过 100 次人工重试和缺失
  应用层 Scope 全部失败关闭，提交后成功审计故障不改变业务成功结果。
- [ ] 死信分页、人工幂等重试、双平台四态对账、租约丢失、受损数据库记录和 R2 审计均通过。

## MCP

- [ ] 官方 TypeScript Client 完成初始化、能力发现、Resource、Prompt 和全部 Tool Schema 校验。
- [ ] R0 只读工具复用应用服务并保持字段脱敏。
- [ ] `approval_timeline_get` 与 REST 时间线返回相同追加动作投影，不包含租户字段、表单正文或内部数据库标识。
- [ ] `erp://approval/templates/published` 与 REST 模板目录返回相同最小字段投影；Resource 不返回节点、解析器、审批人、租户或表单值。
- [ ] `erp://approval/delegations/mine` 与 REST 委托目录返回相同最小投影；MCP 工具列表不存在创建、修改、延长或撤销委托的写 Tool。
- [ ] AI 辅助发起时，MCP 确认命令和审计均不保存表单正文；只允许对 ERP 已存在草稿执行既有 R1 prepare/execute 提交。
- [ ] R1 prepare 不产生业务副作用，只返回 `operationId/digest/riskLevel/expiresAt/confirmationUrl`。
- [ ] ERP 确认页只接受 HttpOnly 会话和可信 Origin；一次性凭据不写 LocalStorage、URL、日志或数据库明文。
- [ ] execute 校验租户、主体、客户端、Scope、命令摘要、版本、有效期和租约；改参、过期、跨客户端均拒绝。
- [ ] 执行进程在业务提交后、确认完成前崩溃，重试不产生重复副作用并返回同一结果。
- [ ] Passkey 登记、清单和撤销仅允许具备 `erp:identity:passkey:manage` 的可信 ERP 会话；服务端没有私钥、口令、平台 Token 或原始生物特征数据。
- [ ] R2 challenge 与租户、主体、浏览器会话及 `operationId` 绑定，五分钟过期且仅消费一次；跨操作、跨会话、重放和并发断言均拒绝。
- [ ] R2 验证精确 Origin、RP ID、凭据归属、签名、UV 标志和计数器；验证证据超过一分钟不能签发确认凭据。
- [ ] R2 调用普通 `/confirm` 路径稳定返回 `MCP_R2_STRONG_AUTH_UNAVAILABLE`；不得通过前端参数、普通 SSO 或省略 UV 绕过。
- [ ] 使用目标 HTTPS 域名在 Chrome、Edge、Safari 及企业实际认证器完成登记、确认、取消、设备丢失/撤销和恢复 UAT。
- [ ] R3 能力不出现在 Tool 列表。

## 发布判定

以下任一条件成立即为 No-Go：跨租户读取/写入、权限绕过、明文敏感数据、审计失败仍返回成功、R2 降级、通知失败改变审批状态、唯一索引冲突、真实平台沙箱未通过。
